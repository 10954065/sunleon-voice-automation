# Known Limitations — Sunleon Voice

Honest, current list. Updated every phase. Nothing here is advertised as working until it's removed from this list.

## Phase 1+2 scope gaps (by design — later phases)

- No real-time voice, no embeddable widget, no actual conversations (Phase 3). Agents can be fully configured and given knowledge, but can't talk yet.
- No billing, plans, usage metering, or payment integration (Phase 4).
- No conversation analytics, leads, or admin console (Phase 5).
- No telephony (Phase 6).
- No custom/cloned voices, no native-language validation (Phase 7).

## Real gaps within Phase 1 itself

- **No rate limiting** on login/registration endpoints. Must be fixed before any public launch.
- **No email verification or password reset flow.** Registration trusts the email address provided; there is no way to recover a lost password yet.
- **No OAuth providers.** Credentials (email/password) only.
- **No MFA.**
- **No E2E test suite yet** (Playwright not configured) — only unit and integration tests exist.
- **No production database provisioned.** Local development uses a Docker Postgres container; a managed provider (Neon / Vercel Postgres) must be chosen and provisioned before any production deployment.
- **No Vercel project linked.** Deployment steps in `docs/DEPLOYMENT_RUNBOOK.md` are written but unexecuted.
- **8 npm audit advisories (5 high, 3 moderate)**: the Phase 1 `eslint-config-next` → `braces` dev-dependency chain, plus a new moderate `mammoth` → `argparse` DoS advisory reachable only through `mammoth`'s CLI, not its `extractRawText()` API used here. Neither reachable from production code or user input. See `docs/SECURITY_MODEL.md`.
- **Invitation emails are not actually sent.** No email provider is configured yet, so there is currently no way to invite a teammate by email in a way they'll receive — only in-app membership creation exists.
- **Test coverage is ~71.4% statements, not the 80% target** (75 tests: unit + real-Postgres integration, up from 67.5%/34 tests in Phase 1). Covers password hashing, validation, RBAC, tenant isolation, agent/version/publish/rollback logic, knowledge-source actions, chunking, SSRF IP classification, local file storage, and tenant-scoped retrieval. The uncovered remainder is concentrated in `src/server/auth/config.ts`/`session.ts`/`sign-in.ts` (same Auth.js-wrapper gap as Phase 1), the real-network branch of `fetchUrlSafely` (redirect-following, response-size limits — deliberately not exercised against real external hosts in a test suite), and the PDF/DOCX branches of `extract.ts` (would need binary test fixtures). Reported honestly rather than padded to hit 80%.
- **No embedding credential configured.** `AI_GATEWAY_API_KEY` is unset in this environment, so every knowledge source currently ends in `FAILED` with a clear error message after extraction/chunking succeed — verified live in a real browser, not assumed. Set the key (see `.env.example`) to unblock real embeddings; no code change needed.
- **Knowledge pipeline runs synchronously in the request** (no background job queue yet — a deliberate YAGNI call for Phase 2's volume, see `docs/DECISIONS.md`-adjacent comment in `src/server/knowledge/pipeline.ts`). Large file uploads or slow crawls will hold the request open; revisit once real usage justifies a queue.
- **Website knowledge sources are a one-time crawl**, not kept in sync with the source page automatically.
- **`prisma migrate dev` has a known false-positive drift** around the hand-managed pgvector HNSW index — see the mandatory operational rule in `docs/DECISIONS.md` before anyone runs a bare `migrate dev` on this project.
- **Next.js dev-tooling auto-generates `AGENTS.md`.** This is Next.js 16's own generated file (not Claude-specific — see its content), regenerated by `next dev`/`next build`; it's committed per its own stated convention to avoid noisy diffs, not an AI-attribution artifact.

## Things this document explicitly does not claim

- No claim of Ghanaian-language support (Twi, Ga, Ewe, etc.) — unvalidated, and not even attempted until Phase 7.
- No claim of telephony availability in Ghana or anywhere else.
- No claim of SOC2/ISO or any other certification.
- No customer testimonials, usage metrics, or case studies exist anywhere in the marketing page — none have been fabricated.
